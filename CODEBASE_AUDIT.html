What is Digital Ketu?

AI-powered WhatsApp chatbot jo Ketu (Sale91.com ka owner) ka "digital twin" hai. Customer ke WhatsApp messages ka auto-reply deta hai Ketu ke style mein (Hinglish).

Customer (WhatsApp)
  → wwbun (WhatsApp Gateway)
  → Digital Ketu API (/api/reply)
  → Claude API (Haiku/Sonnet)
  → Reply back → Customer ko WhatsApp pe

Storage: PostgreSQL (Railway) primary → JSON files fallback → GitHub backup last resort

Bugs Found & Fixed

Bug 1: minutes parameter ignored (main.py) — FIXED

api_ketu_replied mein req.minutes pass nahi ho raha tha. Always default 10 min use hota tha.

Bug 2: Conversation log inconsistency (main.py) — FIXED

Raw message log ho rahi thi, clean (stripped) message nahi. Correction detection fail ho sakta tha.

Bug 3: save_knowledge_to_db() doesn't exist (ketu_only.py) — FIXED

Function name galat tha, save_knowledge() hona chahiye tha. Ketu-only learned patterns DB mein save nahi ho rahe the!

Bug 4: Invalid PostgreSQL syntax (conversation_log.py) — FIXED

ORDER BY ... LIMIT 1 in UPDATE is MySQL syntax. PostgreSQL mein kaam nahi karta. Corrections mark nahi ho rahe the.

Bug 5: Cost alert wrong pricing (engine.py) — FIXED

Sonnet ka reply bhi Haiku ki rate se calculate ho raha tha ($0.80/$4.00 instead of $3.00/$15.00). Cost alerts underreporting.

Known Issues (Not Fixed — Need Discussion)

Issue 1: CORS wildcard in production (main.py:132)

allow_origins=["*"] — Security risk. Specific origins allow karo.

Issue 2: Single DB connection, no pooling (database.py:28)

Single global connection NOT thread-safe. Use psycopg2.pool.ThreadedConnectionPool.

Issue 3: In-memory state loss on redeploy (engine.py:52-76)

Conversations, shutup cooldowns, rate limits — all lost on Railway redeploy.

Issue 4: Settings not persisted (main.py:375)

Toggle changes (auto_reply, followup) are in-memory only. Reset after redeploy.
